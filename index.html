The Starting Point: Why Frontend?

From Python Scripts to Interactive Web Experiences

Our Current World: The Server

우리는 콘솔 출력, 데이터 처리, 비즈니스 로직 실행에 익숙합니다. 이러한 작업은 대부분 '서버'에서 이루어집니다.

Our New Frontier: The Client

프론트엔드는 사용자의 웹 브라우저, 즉 '클라이언트'에서 직접 실행되는 코드를 다룹니다. 사용자의 눈에 보이는 모든 것을 만듭니다.

Key takeaway: 서버(로직)와 클라이언트(표현)의 역할을 구분하는 것이 프론트엔드 개발의 첫걸음입니다.

The Three Pillars of the Web

A core analogy for understanding frontend technologies: Building a House.

HTML: The Structure

집의 뼈대와 설계도

JavaScript: The Functionality

Part 2: Structuring with HTML

HTML is a markup language to describe and structure content.

Anatomy of an Element

<p class="intro">콘텐츠</p>
  • Tag: <p>...</p>
  • Attribute: class="intro"

HTML as Data: The DOM

HTML은 브라우저가 파싱하여 만드는 **데이터 구조(DOM Tree)**로 이해하는 것이 중요합니다. 모든 태그는 트리의 '노드(Node)'가 됩니다.

Part 4: Interacting with JavaScript

JavaScript is a programming language that brings your page to life.

Familiar Concepts

파이썬처럼 변수, 함수, 조건문을 가집니다. 문법은 다르지만 개념은 같습니다.

The Core Mission

JS의 주된 임무는 사용자 이벤트에 반응하고, 페이지의 HTML/CSS를 동적으로 변경(DOM 조작)하는 것입니다.

The Fundamental JavaScript Pattern

Nearly all simple interactions follow this 3-step recipe.

1

SELECT

HTML 요소를 선택

2

LISTEN

'이벤트'를 감지

3

MANIPULATE

DOM을 조작
